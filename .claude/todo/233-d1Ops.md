## Notes from #232 (schema and copy)

- **Schema:** `src/lib/server/db/schema/*.ts`. Column names are the Hasura field names, so
  rows come back in the shapes the stores read. Ids: UUID text made in code (`id()`).
  Timestamps: `toISOString()` strings (`…T10:20:30.123Z`); Hasura sends `…123456+00:00`, so
  the contract tests compare instants, not strings. Booleans 0/1 and JSON as text, both
  mapped back by Drizzle (`mode: 'boolean'`, `mode: 'json'`).
- **What the ops rebuild for the client:**
  - `boards.github` (JSON text) from `github_repo`: `{ owner, repo, full_name }`. In every
    copied row `full_name` is `owner/repo`. Webhook and runner look up `github_repo = ?`.
  - `todos.assigned_to` and `assignee` are gone: all 946 values are in `todo_assignees`. If
    something still reads one `assignee`, use the oldest by `created_at`.
  - `content_preview` = `substr(content, 1, 150)`. `invoiced_hours` is dropped (always 0).
  - `logs` has one time column, `created_at` = the op's `timestamp` (the event time). Clamp
    a client time to now or earlier so the prune (`created_at < ?`, indexed) can catch it.
  - Tokens: `user_secrets(user_id, name, value)`, one row per `github`, `google_calendar`,
    `openai`, `r2`. `users.settings` keeps only `tokens.groq`, the browser's own key. Readers
    to switch: see #230's handover in `232-d1SchemaAndCopy-DONE.md`.
- **Auth.js:** `accounts` has `oauth_token` and `oauth_token_secret` because
  `@auth/d1-adapter` 1.11.3's `linkAccount` inserts them. There is no `sessions` table, so
  the adapter's `deleteUser` (which deletes from `sessions`) must be wrapped or never called.
- **Read budget, measured on todzz-staging:** a full load of the biggest board (tekdok, 371
  open of 560 cards) reads ~10.9k rows with one query per child table
  (`todo_id IN (<board's cards>)`), but ~4.0k with one cards query that has correlated
  sub-selects per card (`json_group_array`). Use the correlated shape. Passing card ids as
  `json_each(?)` costs about the same as the subquery; json_each rows count as reads.
- **Poll:** 3 rows read without the `todos_aggregate`, 576 with it on tekdok (≈ 1.66M rows a
  day for one tab left open). The aggregate must be gone (#231) before the poll reads D1.
- **Refreshing staging:** a full copy into a non-empty DB costs ~160k rows written (deletes
  plus inserts), over the 100k a day, so the script refuses it. Copy single tables (a table
  brings the tables that reference it), or spread a full refresh over two UTC days.
